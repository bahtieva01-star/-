# Модель данных

## 1. Основные сущности

В системе выделяются три основные сущности:

1. `DowntimeRequest` — заявка на устранение простоя насосного оборудования.
2. `Pump` — справочник насосного оборудования.
3. `User` — пользователь системы.

---

## 2. Сущность DowntimeRequest

`DowntimeRequest` является главным объектом системы.

Она содержит информацию о факте простоя насосного оборудования, причине обращения и текущем состоянии работы по заявке.

| Поле | Тип | Ключ | Обязательное | Назначение |
|---|---|---|---|---|
| `id` | integer | PK | да | Уникальный машинный идентификатор заявки |
| `number` | string | UNIQUE | да | Человеческий номер заявки |
| `title` | string | — | да | Краткий заголовок заявки |
| `description` | string | — | да | Подробное описание проблемы |
| `status` | string | — | да | Текущий статус заявки |
| `pumpId` | integer | FK | да | Ссылка на насос из справочника `Pump` |
| `createdByUserId` | integer | FK | да | Пользователь, создавший заявку |
| `assigneeUserId` | integer | FK | нет | Назначенный механик |
| `createdAt` | datetime | — | да | Дата и время создания заявки |

### Назначение полей

`id` используется системой как первичный ключ и идентификатор записи в базе данных.

`number` используется для отображения заявки пользователю. Он не заменяет поле `id`.

`title` содержит краткое описание проблемы.

`description` содержит подробное описание простоя и обнаруженной проблемы.

`status` хранит текущее состояние заявки.

`pumpId` является внешним ключом на справочник насосного оборудования.

`createdByUserId` содержит идентификатор пользователя, который создал заявку.

`assigneeUserId` содержит идентификатор назначенного механика. При создании заявки это поле может быть пустым.

`createdAt` содержит дату и время создания заявки.

---

## 3. Сущность Pump

`Pump` является справочником насосного оборудования.

| Поле | Тип | Ключ | Обязательное | Назначение |
|---|---|---|---|---|
| `id` | integer | PK | да | Уникальный идентификатор насоса |
| `name` | string | — | да | Наименование или обозначение насоса |

Каждый насос имеет собственный числовой `id`.

В заявке хранится только значение `pumpId`, а название насоса не дублируется.

---

## 4. Сущность User

`User` содержит пользователей информационной системы.

| Поле | Тип | Ключ | Обязательное | Назначение |
|---|---|---|---|---|
| `id` | integer | PK | да | Уникальный идентификатор пользователя |
| `name` | string | — | да | Имя пользователя |
| `login` | string | UNIQUE | да | Логин для входа в систему |
| `role` | string | — | да | Роль пользователя |

Основные роли:

- `Master` — сменный мастер;
- `Mechanic` — механик;
- `Manager` — руководитель участка.

---

## 5. Статусы заявки

Для заявки используются только четыре статуса:

| Код | Подпись на экране | Назначение |
|---|---|---|
| `New` | Новая | Заявка создана и ещё не переведена в работу |
| `InProgress` | В работе | Назначенный механик выполняет работу |
| `Closed` | Закрыта | Работа по заявке завершена |
| `Cancelled` | Отменена | Заявка больше не требует выполнения |

Коды статусов `New`, `InProgress`, `Closed`, `Cancelled` являются фиксированными и не изменяются.

---

## 6. Связи между сущностями

### DowntimeRequest → Pump

Один насос может иметь много заявок.

Каждая заявка относится к одному насосу.

Связь:

**Pump 1 : N DowntimeRequest**

В таблице `DowntimeRequest` используется внешний ключ:

`pumpId → Pump.id`

---

### User → DowntimeRequest: создание

Один пользователь может создать много заявок.

Каждая заявка имеет одного пользователя, который её создал.

Связь:

**User 1 : N DowntimeRequest**

В таблице `DowntimeRequest` используется внешний ключ:

`createdByUserId → User.id`

---

### User → DowntimeRequest: назначение

Один механик может быть назначен на много заявок.

У одной заявки может быть не более одного назначенного исполнителя.

При создании новой заявки исполнитель может отсутствовать.

Связь:

**User 1 : N DowntimeRequest**

В таблице `DowntimeRequest` используется внешний ключ:

`assigneeUserId → User.id`

Поле `assigneeUserId` допускает пустое значение до назначения механика.

---

## 7. ER-модель

```text
┌─────────────────────┐
│        User         │
├─────────────────────┤
│ PK id               │
│ name                │
│ login               │
│ role                │
└─────────┬───────────┘
          │
          │ 1:N
          │ createdByUserId
          ▼
┌──────────────────────────────┐
│      DowntimeRequest         │
├──────────────────────────────┤
│ PK id                        │
│ UNIQUE number                │
│ title                        │
│ description                  │
│ status                       │
│ FK pumpId                    │
│ FK createdByUserId           │
│ FK assigneeUserId            │
│ createdAt                    │
└──────────────┬───────────────┘
               │
               │ N:1
               │ pumpId
               ▼
       ┌─────────────────┐
       │      Pump       │
       ├─────────────────┤
       │ PK id           │
       │ name            │
       └─────────────────┘

User 1:N DowntimeRequest
  │
  └── assigneeUserId
      (исполнитель может отсутствовать)
