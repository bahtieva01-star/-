# Контракт API

## 1. Общая информация

API предназначен для учёта и обработки заявок на устранение простоев насосного оборудования.

**Базовый адрес API:** `http://localhost:5000`

**Базовый маршрут:** `/api/downtime-requests`

Формат обмена данными — JSON.

## 2. Основная модель данных

Объект `DowntimeRequest` содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Уникальный идентификатор заявки |
| `number` | string | Номер заявки |
| `title` | string | Название заявки |
| `description` | string | Описание проблемы |
| `status` | string | Статус заявки |
| `pumpId` | integer | Идентификатор насоса |
| `createdByUserId` | integer | Идентификатор создателя |
| `assigneeUserId` | integer или null | Идентификатор ответственного |
| `createdAt` | datetime | Дата создания |

Возможные статусы заявки:

- `New` — новая;
- `InProgress` — в работе;
- `Closed` — закрыта;
- `Cancelled` — отменена.

## 3. Операции API

### 3.1. Создание заявки

**Метод:** `POST`

**Маршрут:** `/api/downtime-requests`

Тело запроса:

```json
{
  "title": "Проверка насоса",
  "description": "Требуется проверить работу насосного оборудования.",
  "pumpId": 1
}
```

Клиент передаёт только данные, необходимые для создания заявки. Поля `id`, `number` и `status` формируются на стороне сервера.

**Успешный ответ:** `201 Created`

Пример ответа:

```json
{
  "id": 1,
  "number": "A-101",
  "title": "Проверка насоса",
  "description": "Требуется проверить работу насосного оборудования.",
  "status": "New",
  "pumpId": 1,
  "createdByUserId": 1,
  "assigneeUserId": null,
  "createdAt": "2026-10-18T10:00:00"
}
```

Возможные ошибки: `400 Bad Request`, `500 Internal Server Error`.

### 3.2. Получение списка заявок

**Метод:** `GET`

**Маршрут:** `/api/downtime-requests`

Возвращает список всех заявок.

**Успешный ответ:** `200 OK`

Пример ответа:

```json
[
  {
    "id": 1,
    "number": "A-101",
    "title": "Проверка насоса",
    "description": "Требуется проверить работу насосного оборудования.",
    "status": "New",
    "pumpId": 1,
    "createdByUserId": 1,
    "assigneeUserId": null,
    "createdAt": "2026-10-18T10:00:00"
  }
]
```

Если заявок нет, сервер возвращает пустой массив:

```json
[]
```

Возможная ошибка: `500 Internal Server Error`.

### 3.3. Получение заявки по идентификатору

**Метод:** `GET`

**Маршрут:** `/api/downtime-requests/{id}`

Возвращает информацию об одной заявке по её идентификатору.

**Успешный ответ:** `200 OK`.

Если заявка не найдена, возвращается `404 Not Found`.

### 3.4. Назначение ответственного

**Метод:** `PATCH`

**Маршрут:** `/api/downtime-requests/{id}/assignee`

Используется для назначения ответственного за выполнение заявки.

Тело запроса:

```json
{
  "assigneeUserId": 2
}
```

**Успешный ответ:** `200 OK`.

Возможные ошибки: `400 Bad Request`, `403 Forbidden`, `404 Not Found`, `500 Internal Server Error`.

### 3.5. Изменение статуса заявки

**Метод:** `PATCH`

**Маршрут:** `/api/downtime-requests/{id}/status`

Используется для изменения текущего статуса заявки.

Тело запроса:

```json
{
  "status": "InProgress"
}
```

**Успешный ответ:** `200 OK`.

Возможные ошибки: `400 Bad Request`, `403 Forbidden`, `404 Not Found`, `500 Internal Server Error`.

## 4. Сводная таблица API

| Метод | Маршрут | Назначение | Успешный ответ |
|---|---|---|---|
| POST | `/api/downtime-requests` | Создание заявки | 201 Created |
| GET | `/api/downtime-requests` | Получение списка заявок | 200 OK |
| GET | `/api/downtime-requests/{id}` | Получение одной заявки | 200 OK, 404 Not Found |
| PATCH | `/api/downtime-requests/{id}/assignee` | Назначение ответственного | 200 OK |
| PATCH | `/api/downtime-requests/{id}/status` | Изменение статуса | 200 OK |

## 5. Обработка ошибок

| Код | Название | Описание |
|---|---|---|
| 400 | Bad Request | Некорректные данные запроса |
| 403 | Forbidden | Недостаточно прав для выполнения операции |
| 404 | Not Found | Заявка или связанный объект не найдены |
| 500 | Internal Server Error | Внутренняя ошибка сервера |

При возникновении ошибки сервер возвращает соответствующий HTTP-код и сообщение с описанием проблемы.

## 6. Отмена заявки

Отдельный метод `DELETE` не используется. Для отмены заявки применяется изменение её статуса через `PATCH /api/downtime-requests/{id}/status` с передачей значения `Cancelled`.

Таким образом, API поддерживает создание, просмотр, назначение ответственного, изменение статуса и отмену заявок.
